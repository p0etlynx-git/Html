ESP32-C3 Super Mini: методика кросс-проверки двух путей сборки

PlatformIO + ESP-IDF как взаимные эталоны для локализации неисправностей. Windows 11 Pro и Ubuntu (GNOME).

Живой документ · целевая плата: ESP32-C3 Super Mini · фреймворк: ESP-IDF

0. Цель и порядок работ

Мы восстанавливаем навык низкоуровневой разработки и поднимаем новую для нас связку VS Code + ESP-IDF + PlatformIO. Чтобы при любом сбое не гадать, «кто виноват», мы держим два независимых пути сборки одного и того же кода. Это даёт точку отсчёта «заведомо работает» и позволяет локализовать проблему за одну проверку.

  1. Создаём два пустых проекта: по одному в каждой системе.
  2. Кладём один и тот же main.c в оба проекта.
  3. Проверяем на своей системе и определяем рабочий путь.
  4. Только после этого ставим чистую экосистему под свою ОС с нужными версиями тулчейнов.

1. Зачем два пути: дифференциальная диагностика

Когда один путь падает, мы собираем тот же код во втором и по результату сужаем область поиска. Чтение таблицы — ниже.

PlatformIOESP-IDFВывод
падаетсобираетсяПроблема в связке PlatformIO / её конфиге / версиях пакетов.
падаетпадаетПроблема в коде или в общем окружении (API IDF, зависимости).
собираетсяпадаетPlatformIO в порядке; проблема в настройке отдельного IDF.
собираетсясобираетсяСборка здорова; ищем проблему в рантайме, а не в компиляции.
Главный подвох: PlatformIO использует свой пакет framework-espidf, и его версия может отличаться от системного IDF. Если API изменился между версиями, можно получить ложную локализацию. Контроль — строка IDF version: ..., которую печатает канарейка в каждой сборке.

2. Общий main.c (канарейка)

Минимальный эталон без внешних зависимостей (без WiFi/роутера): проверяет тулчейн, вывод, чип, FreeRTOS и GPIO, и печатает версию IDF. WiFi — отдельный следующий шаг.

// ============================================================
//  CANARY — эталонный main.c для кросс-проверки двух путей сборки.
//  ОДИН И ТОТ ЖЕ файл кладём в ОБА проекта: PlatformIO и ESP-IDF.
//
//  Доказывает без внешних зависимостей (без WiFi/роутера):
//   - тулчейн компилирует и линкует;
//   - вывод на терминал работает (printf + логгер);
//   - чип определяется (модель, ревизия, MAC, флеш, частота);
//   - FreeRTOS крутится (ядро, планировщик, heap, список задач);
//   - GPIO и светодиод живы.
//  И печатает ВЕРСИЮ IDF — чтобы сравнить оба пути.
// ============================================================

#include <stdio.h>              // printf — «сырой» вывод
#include <string.h>

// ---- FreeRTOS ----
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

// ---- ESP-IDF ----
#include "esp_log.h"            // ESP_LOGI / ESP_LOGW
#include "esp_system.h"         // esp_get_idf_version(), heap
#include "esp_chip_info.h"      // esp_chip_info()
#include "esp_flash.h"          // esp_flash_get_size()
#include "esp_mac.h"            // esp_read_mac() — уникальный ID
#include "driver/gpio.h"        // низкоуровневый доступ к пинам

#define LED_GPIO 8              // встроенный синий светодиод Super Mini
static const char *TAG = "CANARY";

// ---- Шаг 1. Информация о чипе ----
static void print_chip_info(void)
{
    // КЛЮЧЕВАЯ строка: версия IDF, на которой собрался ЭТОТ путь.
    ESP_LOGI(TAG, "IDF version: %s", esp_get_idf_version());

    esp_chip_info_t info;
    esp_chip_info(&info);
    const char *model;
    switch (info.model) {
        case CHIP_ESP32C3: model = "ESP32-C3"; break;
        case CHIP_ESP32S2: model = "ESP32-S2"; break;
        case CHIP_ESP32S3: model = "ESP32-S3"; break;
        case CHIP_ESP32:   model = "ESP32";    break;
        default:           model = "Unknown";  break;
    }
    ESP_LOGI(TAG, "Chip: %s | rev %d | cores %d",
             model, info.revision, info.cores);

    // Частота CPU из конфигурации (для C3 — 80/160 МГц).
    ESP_LOGI(TAG, "CPU freq: %d MHz", CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ);

    // Уникальный ID чипа — MAC-адрес.
    uint8_t mac[6] = {0};
    if (esp_read_mac(mac, ESP_MAC_WIFI_STA) == ESP_OK) {
        ESP_LOGI(TAG, "MAC: %02X:%02X:%02X:%02X:%02X:%02X",
                 mac[0], mac[1], mac[2], mac[3], mac[4], mac[5]);
    }

    // Размер флеш-памяти.
    uint32_t flash_size = 0;
    if (esp_flash_get_size(NULL, &flash_size) == ESP_OK) {
        ESP_LOGI(TAG, "Flash: %lu MB",
                 (unsigned long)(flash_size / (1024 * 1024)));
    }
}

// ---- Шаг 2. Информация о FreeRTOS ----
static void print_freertos_info(void)
{
    ESP_LOGI(TAG, "FreeRTOS kernel: %s | tick: %d Hz",
             tskKERNEL_VERSION_NUMBER, configTICK_RATE_HZ);

    ESP_LOGI(TAG, "Scheduler: %s",
             xTaskGetSchedulerState() == taskSCHEDULER_RUNNING
                 ? "Running" : "NOT running");

    ESP_LOGI(TAG, "Free heap: %lu bytes",
             (unsigned long)esp_get_free_heap_size());

    // Список задач: имя, приоритет, остаток стека (HWM).
    UBaseType_t num = uxTaskGetNumberOfTasks();
    TaskStatus_t *st = pvPortMalloc(num * sizeof(TaskStatus_t));
    if (st != NULL) {
        num = uxTaskGetSystemState(st, num, NULL);
        ESP_LOGI(TAG, "Tasks in system: %d", (int)num);
        for (UBaseType_t i = 0; i < num; i++) {
            ESP_LOGI(TAG, "  %-16s prio:%u stackHWM:%u",
                     st[i].pcTaskName,
                     (unsigned)st[i].uxCurrentPriority,
                     (unsigned)st[i].usStackHighWaterMark);
        }
        vPortFree(st);   // освобождаем массив
    }
}

// ---- Точка входа ----
void app_main(void)
{
    // Даём монитору время подключиться.
    vTaskDelay(pdMS_TO_TICKS(1000));

    // «Сырой» вывод: UART жив ещё до логгера.
    printf("\n===== CANARY: printf works =====\n");

    ESP_LOGI(TAG, "=== Chip info ===");
    print_chip_info();

    ESP_LOGI(TAG, "=== FreeRTOS info ===");
    print_freertos_info();

    // Готовим пин светодиода.
    gpio_reset_pin(LED_GPIO);
    gpio_set_direction(LED_GPIO, GPIO_MODE_OUTPUT);
    ESP_LOGI(TAG, "=== Blinking LED on GPIO%d ===", LED_GPIO);

    // 10 «приветственных» миганий.
    int level = 0;
    for (int i = 0; i < 10; i++) {
        gpio_set_level(LED_GPIO, level);
        level = !level;
        vTaskDelay(pdMS_TO_TICKS(250));
    }
    gpio_set_level(LED_GPIO, 0);

    // Сердцебиение: задача жива, система стабильна.
    while (1) {
        vTaskDelay(pdMS_TO_TICKS(5000));
        ESP_LOGI(TAG, "alive | heap: %lu",
                 (unsigned long)esp_get_free_heap_size());
    }
}

3. Каркас A — PlatformIO

canary-pio/
├── platformio.ini
└── src/
    └── main.c          <-- наш общий файл
; platformio.ini
[env:esp32-c3-supermini]
; PlatformIO сам скачает СВОЙ framework-espidf и тулчейн
; в ~/.platformio/packages — независимо от системного IDF.
platform = espressif32

; Универсальная плата под Super Mini. Альтернативы при странностях
; с флешем: seeed_xiao_esp32c3 или lolin_c3_mini.
board = esp32-c3-devkitm-1

; «Чистый» ESP-IDF, а не Arduino.
framework = espidf

monitor_speed = 115200

                       INCLUDE_DIRS ".")

5. Чистая экосистема под ОС

Windows Windows 11 Pro

  • ESP-IDF (путь B): расширение VS Code «Espressif IDF» → «Configure ESP-IDF Extension» → выбрать стабильную ветку v5.3.x. Расширение ставит IDF и тулчейн в свой каталог и не трогает системный PATH. Альтернатива — онлайн-инсталлятор Espressif, создающий ярлык «ESP-IDF 5.3 CMD» с окружением на сессию.
  • PlatformIO (путь A): расширение «PlatformIO IDE». Платформу подтянет сама.
  • Порт: в диспетчере устройств — COMx. Super Mini использует встроенный USB-Serial-JTAG чипа C3; если порт не виден — поставь драйвер Espressif USB-JTAG (идёт с инсталлятором IDF) или WinUSB через Zadig.
  • Команды PlatformIO: pio run, pio run -t upload, pio device monitor. При необходимости зафиксируй upload_port = COM5 в platformio.ini.

Ubuntu Ubuntu (GNOME)

  • VS Code: sudo snap install code (или .deb с сайта).
  • Зависимости IDF: sudo apt update && sudo apt install git wget flex bison gperf cmake ninja-build ccache libffi-dev libssl-dev dfu-util libusb-1.0-0 python3-venv python3-pip
  • ESP-IDF (путь B): либо расширение VS Code (чисто, без PATH), либо классика: git clone -b v5.3.x --recursive https://github.com/espressif/esp-idf.git, затем ./install.sh esp32c3 и source export.sh в каждой сессии.
  • PlatformIO (путь A): расширение «PlatformIO IDE».
  • Порт и права: C3 определяется как /dev/ttyACM0 (или /dev/ttyUSB0). Обязательно добавь себя в группу dialout и перелогинься: sudo usermod -aG dialout $USER. Без этого прошивка упадёт на правах доступа.
Согласование версий. После установки обеих систем запусти канарейку в каждом пути и сравни строки IDF version: .... Если они разъехались — зафиксируй версии: в PlatformIO это platform = espressif32@<версия>, в IDF — выбранная ветка при установке. Сравнение должно быть «яблоки с яблоками».

6. Подводные камни

  • GPIO8 / светодиод. GPIO8 на C3 — strapping pin, но читается он бутлоадером только в момент сброса. Программа повлиять на это не может, поэтому в коде бояться нечего. Опасность чисто аппаратная: не вешай жёсткую подтяжку на GPIO8. Светодиод через резистор — безопасно.
  • Ошибки без abort. Для диагностики не используй ESP_ERROR_CHECK (он роняет плату в перезагрузку при первой ошибке). Проверяй код и печатай имя ошибки через esp_err_to_name(), затем продолжай — так за один запуск видно максимум.
  • Ubuntu dialout. Самая частая причина «не прошивается» на Linux — отсутствие в группе dialout.
  • Windows драйвер. Если COM-порт не появляется — это драйвер USB-Serial-JTAG, а не плата.

7. Следующие шаги

  1. Добиться, чтобы канарейка собралась и напечаталась в обоих путях.
  2. Сверить версии IDF по логам и зафиксировать их.
  3. Только потом добавлять WiFi (проверка радиочасти) — отдельным модулем поверх живого эталона.
