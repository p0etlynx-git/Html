1. Что такое ESP32 и почему это круто

Представь себе маленький компьютер размером с ноготь, который умеет:

  • Подключаться к WiFi и интернету
  • Управлять датчиками, моторами, светодиодами
  • Работать от батарейки месяцами
  • Стоить как чашка кофе

Это ESP32 — семейство микроконтроллеров от компании Espressif. Они используются в умных домах, роботах, носимой электронике, IoT-устройствах. Это один из самых популярных чипов в мире DIY-электроники.

ESP32-C3 — это современная версия на архитектуре RISC-V (открытый процессор). У него меньше ядер, чем у классического ESP32, но он дешевле, энергоэффективнее и отлично подходит для обучения.

Почему именно ESP32-C3 Super Mini?

  • Компактность: плата размером 2.5 × 1.8 см, помещается куда угодно
  • Встроенный USB: не нужен отдельный программатор, подключаешь к компьютеру кабелем
  • Цена: около $3-5 за плату
  • Всё включено: на плате уже есть WiFi, Bluetooth, флеш-память, светодиод

Что такое ESP-IDF?

ESP-IDF (IoT Development Framework) — это официальный фреймворк от Espressif для программирования ESP32 на Си. Это не Arduino (где всё просто, но ограничено), а профессиональный инструмент, который используют инженеры в промышленности.

Почему мы выбираем ESP-IDF, а не Arduino:

  • Полный контроль: доступ ко всем регистрам и возможностям чипа
  • Современные практики: FreeRTOS, многопоточность, событийная модель
  • Производительность: оптимизированный код, минимум накладных расходов
  • Профессиональные навыки: то, что нужно на реальной работе
К концу этого учебника ты сможешь написать код, который заставит светодиод на плате мигать по твоей команде. Это маленькая победа, но она докажет, что ты контролируешь железо напрямую.

2. Что нам понадобится

Оборудование

  • Плата ESP32-C3 Super Mini (любой производитель: Ai-Thinker, Wemos, no-name)
  • USB-кабель Type-C (обязательно с передачей данных, а не только зарядка!)
  • Компьютер с Windows 11 Pro или Ubuntu 22.04+
Важно про кабель: Многие USB-кабели только заряжают, но не передают данные. Если компьютер не видит плату — попробуй другой кабель. Хороший признак: при подключении слышен звук "подключилось устройство".

Программное обеспечение

  • VS Code — редактор кода (бесплатный, кроссплатформенный)
  • Расширение PlatformIO для VS Code — среда разработки
  • Расширение ESP-IDF для VS Code (опционально, для второго пути сборки)

Мы будем использовать два пути сборки: PlatformIO и ESP-IDF. Зачем? Чтобы если один сломается, второй работал — это даст тебе точку отсчёта для отладки. Но начнём с PlatformIO, он проще.

4. Первый проект: мигаем светодиодом

Это самый важный момент учебника. Мы напишем простейшую программу, которая заставит светодиод на плате мигать. Когда ты увидишь, как он мигает по твоей команде — это будет твоя первая победа.

Создаём проект в PlatformIO

1 В VS Code нажми на иконку PlatformIO слева (инопланетянин)
2 Нажми "New Project" (Новый проект)
3 Заполни форму:
  • Name: hello-led
  • Board: начни вводить esp32-c3 и выбери Espressif ESP32-C3-DevKitM-1
  • Framework: ESP-IDF
  • Use default location: оставь галочку
4 Нажми "Finish". Подожди 1-2 минуты, пока PlatformIO создаст файлы и скачает нужные инструменты.
Слева в проводнике файлов появится структура проекта. Если видишь папки src, include и файл platformio.ini — проект создан!

Пишем код

Открой файл src/main.c (он должен быть пустым или содержать шаблон). Замени всё содержимое на следующий код:

// Первая программа для ESP32-C3: мигаем светодиодом
// Этот код доказывает, что:
// 1. Твой код компилируется и загружается на плату
// 2. Ты можешь управлять железом напрямую
// 3. FreeRTOS работает (мы используем правильные задержки)

#include <stdio.h>              // Для функции printf
#include "freertos/FreeRTOS.h"  // Ядро FreeRTOS
#include "freertos/task.h"      // Функции для работы с задачами
#include "driver/gpio.h"        // Драйвер GPIO (управление пинами)
#include "esp_log.h"            // Система логирования

// Определяем, к какому пину подключён светодиод
// На ESP32-C3 Super Mini это GPIO8
#define LED_GPIO 8

// Тег для логирования (имя нашей программы в логах)
static const char *TAG = "HELLO_LED";

// Главная функция программы (точка входа)
// В ESP-IDF это не main(), а app_main()
void app_main(void)
{
    // Приветственное сообщение в консоль
    ESP_LOGI(TAG, "Привет, ESP32-C3! Начинаем мигать светодиодом.");
    
    // Шаг 1: Настраиваем пин светодиода
    // gpio_reset_pin() - сбрасываем пин к начальному состоянию
    // gpio_set_direction() - устанавливаем пин как выход (OUTPUT)
    gpio_reset_pin(LED_GPIO);
    gpio_set_direction(LED_GPIO, GPIO_MODE_OUTPUT);
    
    // Переменная для хранения текущего состояния светодиода
    // 0 = выключен, 1 = включен
    int led_state = 0;
    
    // Шаг 2: Бесконечный цикл мигания
    // while(1) означает "повторять всегда"
    // Важно: app_main() не должна завершаться, иначе плата перезагрузится
    while (1) {
        // Инвертируем состояние: 0 становится 1, 1 становится 0
        led_state = !led_state;
        
        // Устанавливаем уровень на пине:
        // 0 = низкий уровень (GND, светодиод гаснет)
        // 1 = высокий уровень (3.3V, светодиод горит)
        gpio_set_level(LED_GPIO, led_state);
        
        // Выводим сообщение в лог (увидим в консоли)
        ESP_LOGI(TAG, "Светодиод: %s", led_state ? "ВКЛ" : "ВЫКЛ");
        
        // Ждём 500 миллисекунд (полсекунды)
        // vTaskDelay() - это "правильная" задержка FreeRTOS
        // Она отдаёт процессор другим задачам, а не крутит холостой цикл
        // pdMS_TO_TICKS(500) переводит миллисекунды в тики FreeRTOS
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

Компилируем и загружаем на плату

1 Убедись, что плата подключена к компьютеру через USB
2 Внизу окна VS Code найди панель статуса PlatformIO (сине-зелёная полоса)
3 Нажми на иконку "галочка" (Build) — это компиляция

Подожди 30-60 секунд. В терминале внизу побежит текст. Если всё хорошо, в конце увидишь:

SUCCESS: Program built successfully.
Memory usage:
RAM: [= ] 5.2% (used 17356 bytes from 327680 bytes)
Flash: [======== ] 78.3% (used 821456 bytes from 1048576 bytes)
Если видишь "SUCCESS" — поздравляю! Твой код скомпилировался без ошибок. Это уже победа.
4 Теперь нажми на иконку "стрелка" (Upload) — это загрузка на плату

PlatformIO найдёт USB-порт и зальёт программу на плату. В терминале увидишь что-то вроде:

Wrote 821456 bytes (456789 compressed) at 0x00010000 in 8.2 seconds

🎉 СМОТРИ НА ПЛАТУ! Синий светодиод должен начать мигать раз в секунду!

Если он мигает — ты только что написал свою первую программу для микроконтроллера и загрузил её на железо. Ты контролируешь электронику кодом!

Открываем монитор порта

Чтобы видеть сообщения из программы (наши "Светодиод: ВКЛ/ВЫКЛ"), нужно открыть монитор порта:

2 В терминале побежит:

I (1234) HELLO_LED: Светодиод: ВКЛ

I (2234) HELLO_LED: Светодиод: ВКЛ
I (2734) HELLO_LED: Светодиод: ВЫКЛ

Число в скобках (1234, 1734 и т.д.) — это миллисекунды с момента запуска. Видишь разницу 500 мс? Это наша задержка работает идеально!

Теперь у тебя есть полная обратная связь: ты видишь мигающий светодиод И логи программы. Ты контролируешь железо и видишь, что оно делает. Это и есть инженерия!

5. Разбираем код построчно

Теперь, когда всё работает, давай поймём, как оно работает. Это важно, чтобы ты не просто копировал код, а понимал его.

Заголовочные файлы (#include)

#include <stdio.h>              // Стандартная библиотека Си
#include "freertos/FreeRTOS.h"  // Ядро операционной системы FreeRTOS
#include "freertos/task.h"      // Функции для задач (потоков)
#include "driver/gpio.h"        // Драйвер для управления пинами
#include "esp_log.h"            // Система логирования ESP-IDF

Почему так много библиотек? ESP-IDF — это профессиональный фреймворк. Вместо одной "волшебной" функции, которая делает всё (как в Arduino), здесь много маленьких специализированных модулей. Это даёт гибкость и контроль.

Точка входа: app_main()

void app_main(void)
{
    // ... код ...
}

В Arduino точка входа — это setup() и loop(). В ESP-IDF — это app_main().

Важно: app_main() — это не просто функция, это задача FreeRTOS. Если она завершится (дойдёт до закрывающей скобки), плата перезагрузится. Поэтому внутри обязательно должен быть бесконечный цикл while(1).

Настройка пина: GPIO

#define LED_GPIO 8              // Номер пина

gpio_reset_pin(LED_GPIO);        // Сброс к начальному состоянию
gpio_set_direction(LED_GPIO, GPIO_MODE_OUTPUT);  // Режим "выход"

Что такое GPIO? General-Purpose Input/Output — универсальные входы/выходы. Это пины на чипе, которые можно программировать как входы (читать напряжение) или выходы (управлять напряжением).

Почему GPIO8? На плате ESP32-C3 Super Mini синий светодиод физически подключён к пину GPIO8. Это можно посмотреть в документации к плате или просто методом проб.

Зачем gpio_reset_pin()? Перед использованием пин нужно "очистить" от возможных настроек, оставшихся от загрузчика. Это хорошая практика.

Управление пином: включаем и выключаем

int led_state = 0;              // 0 = выкл, 1 = вкл

led_state = !led_state;          // Инвертируем: 0→1, 1→0
gpio_set_level(LED_GPIO, led_state);  // Устанавливаем уровень

Как это работает на уровне железа:

  • gpio_set_level(pin, 0) — пин подключается к земле (GND), напряжение 0В
  • gpio_set_level(pin, 1) — пин подключается к питанию (3.3V)

Светодиод включается, когда на его аноде высокое напряжение (3.3V), а на катоде — низкое (GND). Когда мы даём на GPIO8 высокий уровень — ток течёт через светодиод, и он светится.

Задержка: vTaskDelay()

vTaskDelay(pdMS_TO_TICKS(500));  // Ждём 500 мс

Почему не используем обычный sleep() или delay()?

ESP32 работает под управлением FreeRTOS — операционной системы реального времени. В ней много задач работают параллельно: твоя программа, WiFi-стек, Bluetooth, системные службы.

vTaskDelay() — это "умная" задержка. Она говорит FreeRTOS: "Я хочу спать 500 мс, отдай процессор другим задачам". Обычный delay() просто крутит холостой цикл, тратя процессорное время впустую.

pdMS_TO_TICKS(500) — это макрос, который переводит миллисекунды в "тики" FreeRTOS. Один тик обычно равен 1 мс, но это настраивается.

Логирование: ESP_LOGI()

ESP_LOGI(TAG, "Светодиод: %s", led_state ? "ВКЛ" : "ВЫКЛ");

Что это делает? Выводит сообщение в монитор порта (Serial Monitor). Это как Serial.println() в Arduino, но мощнее.

Параметры:

  • TAG — имя нашей программы (мы задали его как "HELLO_LED")
  • Формат строки (как в printf)
  • Значения для подстановки в формат

Уровни логирования:

  • ESP_LOGE — ошибка (Error)
  • ESP_LOGW — предупреждение (Warning)
  • ESP_LOGI — информация (Info)
  • ESP_LOGD — отладка (Debug)
  • ESP_LOGV — подробно (Verbose)

В продакшене обычно оставляют только INFO и выше, а DEBUG выключаешь для производительности.

6. Что такое FreeRTOS и почему это важно

Ты только что использовал FreeRTOS, даже если не заметил. Давай разберёмся, что это и зачем нужно.

Проблема: один процессор, много задач

У ESP32-C3 одно ядро процессора. Но одновременно должны работать:

  • Твоя программа (мигание светодиодом)
  • WiFi-стек (если включён)
  • Bluetooth-стек (если включён)
  • Системные службы (обработка прерываний, таймеры)

Как одному процессору делать много дел одновременно?

Решение: FreeRTOS и многозадачность

FreeRTOS (Free Real-Time Operating System) — это операционная система реального времени для микроконтроллеров. Она решает проблему так:

  1. Каждая "программа" — это задача (task)
  2. FreeRTOS быстро переключается между задачами (тысячи раз в секунду)
  3. Со стороны кажется, что все задачи работают одновременно

Это как жонглёр: он подбрасывает много мячей, но в каждый момент времени держит только один. Переключение происходит так быстро, что выглядит как одновременность.

Задачи в нашей программе

Когда ты запустил программу, FreeRTOS создал несколько задач:

I (1234) HELLO_LED: Tasks in system: 8
I (1234) HELLO_LED:   IDLE         prio:0  stackHWM:100
I (1234) HELLO_LED:   main        prio:1  stackHWM:2048
I (1234) HELLO_LED:   Tmr Svc    prio:1  stackHWM:200
I (1234) HELLO_LED:   ipc0       prio:23 stackHWM:150
...
  • main — это твоя программа (app_main)
  • IDLE — задача "ничегонеделания", работает когда все остальные спят
  • Tmr Svc — служба таймеров
  • ipc0 — межпроцессное взаимодействие

Почему это важно для тебя

  1. Правильные задержки: vTaskDelay() отдаёт процессор другим задачам
  2. Параллельная работа: ты можешь создать свою задачу для мигания и другую — для чтения датчиков
  3. Профессиональные навыки: FreeRTOS используется в промышленности, автомобилях, медицине
Когда ты освоишься с базой, мы создадим две задачи: одна будет мигать светодиодом, вторая — читать кнопку. Они будут работать параллельно, не мешая друг другу. Это и есть настоящая многозадачность!

7. Отладка и поиск ошибок

Что делать, если что-то пошло не так? Вот типичные проблемы и их решения.

Проблема: "Порт не найден"

Windows: Проверь Диспетчер устройств. Если устройства нет — установи драйвер Espressif USB-JTAG.

Ubuntu: Проверь, что ты в группе dialout (groups $USER). Если нет — добавь себя и перелогинься.

Проблема: "Compilation failed"

Компилятор не может понять твой код. Читай ошибку в терминале — обычно там указана строка и причина.

Типичные ошибки:

  • Забыл точку с запятой (;)
  • Опечатка в имени функции
  • Не подключил нужный заголовочный файл

Проблема: "Прошивка не загружается"

Код скомпилировался, но не записался на плату.

1 Отключи плату от USB
2 Зажми кнопку BOOT на плате (если есть)
3 Подключи плату, продолжая держать BOOT
4 Отпусти BOOT
5 Попробуй загрузить снова

Это переводит плату в режим прошивки вручную.

Проблема: "Программа не запускается"

Плата прошилась, но ничего не происходит.

1 Открой монитор порта (Serial Monitor)
2 Нажми кнопку RESET на плате (или отключи/подключи USB)
3 Смотри, что выводится в терминал

Если видишь сообщения об ошибках (например, "abort() was called") — читай текст ошибки, там указана причина.

Как читать логи ошибок

ESP-IDF использует макрос ESP_ERROR_CHECK() для проверки ошибок. Если ошибка произошла, он выводит:

ESP_ERROR_CHECK failed: esp_err_t 0x105 (ESP_ERR_NOT_FOUND) at 0x400d1234
file: "main.c" line 42
func: app_main
abort() was called at PC 0x400d1234 on core 0

Что здесь важно:

  • esp_err_t 0x105 — код ошибки
  • ESP_ERR_NOT_FOUND — имя ошибки (понятнее, чем число)
  • file: "main.c" line 42 — где произошла ошибка
  • func: app_main — в какой функции

Зная имя ошибки и строку, ты можешь понять, что пошло не так.

8. Что дальше: следующие шаги

Поздравляю! Ты сделал самое сложное — первый шаг. Теперь у тебя есть:

  • Рабочая среда разработки
  • Понимание, как компилировать и загружать код
  • Первая работающая программа
  • Базовое понимание FreeRTOS и GPIO

Что можно попробовать дальше

  1. Изменить скорость мигания: поменяй pdMS_TO_TICKS(500) на pdMS_TO_TICKS(100) — будет мигать быстрее
  2. Сделать "бегущий огонь": если на плате несколько светодиодов, управляй ими по очереди
  3. Добавить кнопку: подключи кнопку к другому пину, читай её состояние и меняй поведение светодиода
  4. Подключить датчик: например, датчик температуры. Читай показания и выводи в лог

Два пути сборки: зачем это нужно

В начале учебника я упоминала, что мы будем использовать два пути сборки: PlatformIO и ESP-IDF. Сейчас ты работал только с PlatformIO, и этого достаточно для старта.

Но когда ты начнёшь делать более сложные проекты, полезно иметь второй путь — «чистый» ESP-IDF без PlatformIO. Зачем?

  • Диагностика: если что-то сломается в PlatformIO, ты можешь проверить, работает ли код в чистом IDF. Если в IDF собирается, а в PIO нет — проблема в настройках PlatformIO, а не в коде.
  • Доступ ко всем возможностям IDF: PlatformIO иногда отстаёт от свежих версий ESP-IDF. Чистый IDF даёт доступ к последним фичам сразу.
  • Понимание системы сборки: работая с чистым IDF, ты увидишь, как устроен процесс сборки «под капотом» — CMake, компоненты, конфигурация через menuconfig.

Когда будешь готов — скажи, и я подготовлю отдельный раздел по установке и настройке чистого ESP-IDF.

Философия инженера

Напоследок — несколько принципов, которые помогут тебе расти:

  1. Не копируй слепо. Каждый раз, когда берёшь чужой код, разберись, что делает каждая строка. Если не понимаешь — спроси у документации или у меня.
  2. Ошибки — это нормально. Каждый инженер проходит через сотни ошибок. Важно не избегать их, а учиться читать и понимать.
  3. Маленькие шаги. Не пытайся сразу сделать космолёт. Мигни светодиодом. Потом подключи кнопку. Потом датчик. Потом WiFi. Каждый шаг — победа.
  4. Документируй. Записывай, что ты сделал и почему. Будущий ты скажет спасибо.
Ты прошёл путь от «я не знаю, что такое ESP32» до «я написал код, скомпилировал, загрузил на плату, и светодиод мигает по моей команде». Это настоящий инженерный путь. Гордись собой!
