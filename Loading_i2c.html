📡 Визуализация активности шины I2C

Аппаратный мониторинг загрузки шины через ШИМ-индикатор.
чистый регистровый доступ без HAL-блокировок ISR-safe

💡 2. Описание идеи

Мы строим индикатор интенсивности трафика на шине I2C. Вместо дискретного «горит/не горит» светодиод плавно меняет яркость пропорционально частоте пакетов.

  • Ядро идеи: В прерывании по завершению I2C (DMA или событие) мы считываем текущее значение счётчика ШИМ-таймера.
  • Логика изменения яркости: Если счётчик находится выше середины периода — уменьшаем яркость (сигнал пришёл поздно, шина свободна). Если ниже — увеличиваем (активность высокая).
  • Никаких дополнительных таймеров: Используется единственный ШИМ-таймер, который и так генерирует сигнал на светодиод.
  • Фоновый режим: Весь код выполняется в прерываниях, не нагружая основной поток (или FreeRTOS-задачи).
✅ Ключевое преимущество: Минимальное вмешательство в периферию. Один таймер, одно прерывание, никаких внешних счётчиков.

⚙️ 3. Алгоритм работы

Псевдокод (платформонезависимый):

// Глобальные переменные (volatile, aligned)
volatile uint32_t brightness = 500;   // текущая яркость (0…1000)
const uint32_t STEP = 8;              // шаг изменения
const uint32_t MAX_BRIGHT = 1000;

// ISR по завершению I2C-передачи
void I2C_Complete_ISR(void) {
    // 1. Фиксируем текущий счётчик ШИМ-таймера
    uint32_t cnt = TIMER->CNT;
    uint32_t half = TIMER->ARR / 2;

    // 2. Корректируем яркость
    if (cnt > half) {
        if (brightness < MAX_BRIGHT) brightness += STEP;
    } else {
        if (brightness > 0) brightness -= STEP;
    }

    // 3. Обновляем регистр сравнения (скважность)
    TIMER->CCR = brightness;

    // 4. Сбрасываем флаг прерывания (зависит от платформы)
}
⚠️ Важное замечание: half = ARR / 2 вычисляется один раз при инициализации, а не в ISR. В примере выше — для наглядности.

🧩 4. Совместимость и подводные камни

🔵 STM32 (HAL)

  • Используйте TIMx (не SysTick).
  • Выравнивание __attribute__((aligned(4))) обязательно.
  • Приоритет ISR — самый низкий (≥ 5).
  • Операции с CCR и CNT — через регистры, минуя HAL.

🟢 ESP32 (ESP‑IDF)

  • Используйте GPTimer + LEDC.
  • Не отключайте прерывания глобально.
  • Все вызовы в ISR — только _ISR-safe.
  • Приоритет ISR — 1 (низкий).

🔴 AVR (8‑бит)

  • Используйте Timer1 в режиме Fast PWM.
  • Чтение TCNT1 и запись OCR1A — напрямую.
  • Переменные volatile uint16_t — атомарны по чтению/записи.
  • Прерывания по I2C (TWINT) — стандартный вектор.

⚠️ Общие подводные камни

  • Выравнивание: На STM32 критично для 32‑битных переменных, используемых в ISR. Всегда aligned(4).
  • Атомарность: На STM32 запись в CCR атомарна, а brightness++ — нет. Используйте brightness += STEP как одну операцию RMW, но если есть риск гонки — оборачивайте в критическую секцию.
  • Приоритеты: Если ваш ISR выше системного — вы завалите HAL, RTOS или Wi‑Fi.
  • Длительность ISR: Чтение регистра + сравнение + запись — это < 1 мкс на Cortex‑M. Не вызывайте printf, HAL_Delay или vTaskDelay.

🔵 5. Реализация на STM32 (CubeIDE / HAL)

CMSIS регистровый доступ без HAL-блокировок

/* ============================================================
   STM32 – индикатор активности I2C через ШИМ (TIM2, канал 1)
   ============================================================ */

#include "stm32f4xx.h"   // под ваш конкретный камень

// ——— Глобальные переменные (выровнены, volatile) ———
volatile uint32_t led_brightness __attribute__((aligned(4))) = 500;
const uint32_t STEP = 8;
const uint32_t MAX_BRIGHT = 999;

// ——— Инициализация ШИМ (вызывается один раз) ———
void pwm_init(void) {
    // 1. Тактирование TIM2
    RCC->APB1ENR |= RCC_APB1ENR_TIM2EN;

    // 2. Настройка GPIO (PA0 – TIM2_CH1)
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    GPIOA->MODER   |= GPIO_MODER_MODER0_1;   // AF
    GPIOA->AFR[0]  |= (1 << 0);             // AF1 = TIM2_CH1

    // 3. Настройка TIM2: PWM mode 1, частота ~1 кГц
    TIM2->PSC  = 8400 - 1;       // 84 МГц → 10 кГц
    TIM2->ARR  = 1000 - 1;        // период 1000 тиков → 100 мс
    TIM2->CCMR1 = TIM_CCMR1_OC1M_1 | TIM_CCMR1_OC1M_2; // PWM mode 1
    TIM2->CCER  = TIM_CCER_CC1E;  // выход включён
    TIM2->CR1  |= TIM_CR1_CEN;    // запуск таймера

    // 4. Начальная яркость 50%
    TIM2->CCR1 = led_brightness;
}

// ——— ISR по завершению I2C-передачи (колбэк HAL) ———
void HAL_I2C_MasterTxCpltCallback(I2C_HandleTypeDef *hi2c) {
    // 1. Читаем счётчик (атомарно, 32 бита)
    uint32_t cnt = TIM2->CNT;

    // 2. Сравниваем с половиной периода (вычислено один раз при старте)
    //    HALF_PERIOD = TIM2->ARR / 2 (вынесено в константу)
    if (cnt > 500) {
        if (led_brightness < MAX_BRIGHT) {
            led_brightness += STEP;
        }
    } else {
        if (led_brightness > 0) {
            led_brightness -= STEP;
        }
    }

    // 3. Запись в регистр сравнения (атомарно)
    TIM2->CCR1 = led_brightness;

    // 4. Сброс флага прерывания I2C (если нужно)
    //    __HAL_I2C_CLEAR_FLAG(hi2c, ...);
}
⚠️ STM32: Убедитесь, что приоритет прерывания I2C ниже, чем у системных (NVIC_SetPriority(<IRQ>, 5, 0)).

🟢 6. Реализация на ESP32 (ESP‑IDF)

GPTimer LEDC ISR‑safe

/* ============================================================
   ESP32 – индикатор активности I2C через ШИМ (LEDC + GPTimer)
   ============================================================ */

#include "driver/ledc.h"
#include "driver/gptimer.h"

// ——— Глобальные переменные ———
volatile uint32_t led_brightness = 500;
const uint32_t STEP = 8;
const uint32_t MAX_BRIGHT = 1000;

// ——— Инициализация LEDC (ШИМ) ———
void pwm_init(void) {
    ledc_timer_config_t timer_cfg = {
        .speed_mode       = LEDC_LOW_SPEED_MODE,
        .timer_num        = LEDC_TIMER_0,
        .freq_hz          = 1000,
        .duty_resolution  = LEDC_TIMER_10_BIT, // 0…1023
        .clk_cfg          = LEDC_AUTO_CLK
    };
    ledc_timer_config(&timer_cfg);

    ledc_channel_config_t ch_cfg = {
        .speed_mode     = LEDC_LOW_SPEED_MODE,
        .channel        = LEDC_CHANNEL_0,
        .timer_sel      = LEDC_TIMER_0,
        .gpio_num       = GPIO_NUM_2,
        .duty           = led_brightness
    };
    ledc_channel_config(&ch_cfg);
}

// ——— Инициализация GPTimer (только для счётчика, не для ШИМ) ———
void counter_init(void) {
    gptimer_config_t cfg = {
        .resolution_hz = 1 * 1000 * 1000, // 1 МГц
        .direction     = GPTIMER_COUNT_UP,
    };
    gptimer_handle_t timer;
    gptimer_new_timer(&cfg, &timer);
    gptimer_enable(timer);
    gptimer_start(timer);
    // Счётчик просто бежит, мы читаем его значение в ISR
}

// ——— ISR по завершению I2C (драйвер ESP-IDF) ———
void i2c_complete_isr(void *arg) {
    // 1. Читаем текущий счётчик GPTimer (ISR-safe)
    uint64_t cnt = 0;
    gptimer_get_raw_count(timer_handle, &cnt);

    // 2. Половина периода = 500000 (при 1 МГц и периоде 1 с)
    //    Вынесено в константу HALF_PERIOD
    if (cnt > 500000) {
        if (led_brightness < MAX_BRIGHT) led_brightness += STEP;
    } else {
        if (led_brightness > 0) led_brightness -= STEP;
    }

    // 3. Обновляем скважность LEDC (ISR-safe)
    ledc_set_duty(LEDC_LOW_SPEED_MODE, LEDC_CHANNEL_0, led_brightness);
    ledc_update_duty(LEDC_LOW_SPEED_MODE, LEDC_CHANNEL_0);
}
✅ ESP32: Не используем taskENTER_CRITICAL() в ISR. Все вызовы — ISR-безопасны.

🔴 7. Реализация на AVR (Arduino / avr‑libc)

Timer1 Fast PWM TWI

/* ============================================================
   AVR (ATmega328p) – индикатор активности I2C через ШИМ (Timer1)
   ============================================================ */

#include <avr/io.h>
#include <avr/interrupt.h>

// ——— Глобальные переменные (volatile, 16 бит) ———
volatile uint16_t led_brightness = 500;
const uint16_t STEP = 8;
const uint16_t MAX_BRIGHT = 999;

// ——— Инициализация ШИМ (Fast PWM, OC1A) ———
void pwm_init(void) {
    DDRB |= (1 << PB1);          // OC1A как выход

    TCCR1A = (1 << WGM10) | (1 << WGM11) | (1 << COM1A1); // Fast PWM 10-bit
    TCCR1B = (1 << WGM12) | (1 << CS10);                  // clk/1

    OCR1A = led_brightness;      // начальная яркость
}

// ——— ISR по завершению I2C (вектор TWI) ———
ISR(TWI_vect) {
    // 1. Читаем счётчик Timer1 (16 бит, атомарно)
    uint16_t cnt = TCNT1;

    // 2. Сравниваем с половиной периода (1023 / 2 ≈ 511)
    if (cnt > 511) {
        if (led_brightness < MAX_BRIGHT) led_brightness += STEP;
    } else {
        if (led_brightness > 0) led_brightness -= STEP;
    }

    // 3. Обновляем регистр сравнения (атомарно)
    OCR1A = led_brightness;

    // 4. Сброс флага прерывания TWI (аппаратно, явно не требуется)
    //    TWCR |= (1 << TWINT);
}
⚠️ AVR: Для корректной работы I2C (TWI) не забудьте настроить скорость и разрешить прерывания sei().

📌 Заключение

Мы построили аппаратно-независимый алгоритм визуализации загрузки шины I2C, который работает на трёх принципиально разных архитектурах.

  • STM32: Регистровый доступ, низкий приоритет ISR, строгое выравнивание.
  • ESP32: ISR-безопасные вызовы, без глобальных блокировок, низкий приоритет.
  • AVR: Прямая работа с регистрами, атомарность 16‑битных операций.

Этот подход можно адаптировать под любую периферию: SPI, UART, внешние прерывания — везде, где есть прерывания и ШИМ-таймер.

🏁 Итог: Мы получили красивый, ресурсоэффективный и переносимый индикатор активности, который не требует внешних компонентов и работает в фоне, не нагружая основную логику.

⚡ Настройка приоритетов прерываний (ISR)

Корректный приоритет — единственное, что спасает от падения системы, зависания Wi-Fi и сбоев DMA. Ниже — готовые фрагменты для каждой платформы.

🔵 STM32 (HAL / CMSIS)

/* I2C1 – самый низкий приоритет (5) */
HAL_NVIC_SetPriority(I2C1_EV_IRQn, 5, 0);
HAL_NVIC_EnableIRQ(I2C1_EV_IRQn);

/* TIM2 – ещё ниже (6), чтобы не мешать I2C */
HAL_NVIC_SetPriority(TIM2_IRQn, 6, 0);
HAL_NVIC_EnableIRQ(TIM2_IRQn);
⚠️ Чем выше число — тем ниже приоритет.

🟢 ESP32 (ESP‑IDF)

/* I2C – низкий приоритет (1) */
i2c_config_t conf = {
    .intr_priority = 1,   // 1 — минимальный
    // ...
};

/* GPTimer – тоже 1 */
gptimer_config_t timer_cfg = {
    .intr_priority = 1,
    // ...
};
✅ На ESP32 приоритет 1 — самый низкий. Не трогаем 0 — там системные прерывания.

🔴 AVR (avr‑libc)

/* AVR — аппаратные приоритеты фиксированы:
   - RESET (высший)
   - INT0
   - TWI (I2C) — средний
   - TIMER1 — низший
*/
/* Всё, что нужно — разрешить прерывания */
sei();  // глобально
⚠️ На AVR приоритеты не настраиваются. Но вектор TWI имеет приоритет выше, чем TIMER1 — это безопасно.

💡 Три светодиода — максимум наглядности

Вместо того чтобы мучиться с одним ШИМ-каналом и мультиплексированием, мы просто берём три светодиода и назначаем каждому свою шину.

✅ Преимущества:
  • Каждая шина — отдельный цвет. Глаз мгновенно определяет проблемную.
  • Нет конфликтов прерываний — каждое обновляет только свой регистр.
  • Легко масштабировать — добавили шину, добавили светодиод.
  • Ног на МК много — это не серверная стойка, это творчество.

⚙️ Принцип работы (напоминание)

  • Каждая шина (I2C, SPI, UART) имеет свой ШИМ-таймер и свой светодиод.
  • В прерывании по завершению передачи мы читаем CNT таймера и корректируем CCR (яркость).
  • Нет IF — только линейный код.
  • Приоритет прерываний — самый низкий, чтобы не мешать системным задачам.
⚠️ Важно: Если таймеров на всех не хватает — можно использовать один таймер с тремя каналами (STM32 это позволяет) или сделать аппаратный мультиплексор на логике.
